# NodeFinder

*(working title - rename before publishing; check for a CurseForge naming collision first)*

A World of Warcraft: Forever addon that points you to the nearest herb or ore node you've chosen, using the nodes your minimap tracking is showing **right now** - not remembered or possible spawn spots.

## How it works

Addons can't list nearby game objects, and the minimap API has no call that returns tracked blips. But the minimap does answer "what is under this point": `Minimap:UpdateMouseoverAtPoint(x, y)` moves its mouseover, and `GameTooltip:SetMinimapMouseover()` fills a tooltip with whatever is there (this is how Blizzard builds the blip tooltip). NodeFinder probes a grid of points over the minimap about once a second, reads the node names, and converts each hit to world coordinates. The arrow then uses the player's live position, so it stays correct while you run between scans.

This was proven in-game with a throwaway experiment (NodeProbe) before anything was built: the point is in raw screen pixels, names come back as plain text (not secret values), and the answer is ready the same frame.

- A node above or below you has an inline arrow icon in front of its tooltip name (`|TInterface\Minimap-PositionArrows:…|tCopper Vein`, found with `/nf probe`). The scan strips it to match the name, and keeps it so the arrow's label shows the minimap's own up/down marker. Distance is horizontal only, like the minimap itself.
- Scans use a private hidden tooltip so your own tooltips are never disturbed.
- Scanning is skipped while the mouse is over the minimap, while on a taxi, and when nothing is ticked.
- Probes are spread over a few frames (about 100 per frame), and one scan is roughly 1,100 probes.

## Tracking

By default NodeFinder keeps tracking in step with your selections (`Modules/Tracking.lua`). Find Minerals is on while any ore is ticked and off when none is, likewise Find Herbs, and both come back on after you die (the client switches tracking off on death). It uses `C_Minimap.SetTracking`, the same call GatherLite uses, and only touches those two spells, never your other trackers.

- It never tries while you're in combat or dead; it retries from the events that fire when that changes (`PLAYER_REGEN_ENABLED`, `PLAYER_ALIVE`, `PLAYER_UNGHOST`, `MINIMAP_UPDATE_TRACKING`) plus a 5-second safety check.
- If switching one tracker on keeps switching the other off, it gives up after a few attempts and tells you, rather than flipping them forever.
- Untick **Switch Find Minerals/Herbs to match** in the options window (or `/nf tracking off`) to control tracking yourself. It also stays hands-off while the addon itself is switched off.

## Light beam on the node you reach

The arrow gets you close; the beam picks out the exact bush or vein. Herbs and ore blend into the terrain, so as you get near a node you ticked, a beam of light rises from it, tinted by node type (blue for ore, green for herbs by default, with eight colour presets in the options window).

- **Dim** until you can reach it, **bright with a ring pulse** once you can gather it, **grey** if the game won't let you (skill too low).
- **Only ticked nodes.** Nodes you left unticked get nothing.
- **Range.** It uses the game's own "soft interact" target, which is the nearest thing you could interact with, out to about 15 yards, one object at a time. Addons can't draw in the 3D world and the client has no world-to-screen call, so nothing can mark a node farther away than that. Past 15 yards, follow the arrow.
- **How it works.** The game can give its soft-interact target a nameplate, and a nameplate is the one UI frame the game keeps pinned over a world object. NodeFinder turns that system on (the `SoftTarget*` console variables, saved first and put back when you switch the beam off), opens the nameplate only while the target is a node you ticked, and hangs the beam on it. Whether the target is a node comes from its name, or, if the client won't give the name, from its cursor icon (Mine / Gather Herbs). The beam textures are generated by `tools/make_highlight_textures.py`.
- **Combat.** Console variables can't change in combat, so the beam waits until the fight is over.

### Together with ForeverLootSparkles

ForeverLootSparkles also sparkles ore and herbs, using the same game system. If both are installed, NodeFinder handles ore and herb nodes (the beam) and ForeverLootSparkles keeps everything else: quest items, quest objects, corpses with loot.

It works by switching off ForeverLootSparkles' two ore/herb options for the session (they live in its saved-variables table, which it reads whenever it decides what to sparkle) and putting them back when you log out, before the game saves, so nothing is changed on disk. If you switch one back on in ForeverLootSparkles' own options, NodeFinder takes that as your choice, stops taking over, and says so. `/nf highlight takeover off` (or the options checkbox) hands them back at any time. The two addons also share one nameplate switch; under ForeverLootSparkles NodeFinder only closes it when the target is clearly neither a quest object nor a corpse.

## Use

- Tracking turns on by itself (above). If you've turned that off, turn on **Find Minerals** and/or **Find Herbs** yourself. Both can be on at once.
- `/nf` (or right-click the arrow) opens the node list: tick the nodes you want. Unticked nodes never show.
- The arrow shows the nearest ticked node and its distance in yards. Drag it to move it.
- When nothing ticked is in range it says so, or tells you which tracking spell is off.

Commands: `/nf` options, `on`, `off`, `status` (last scan, tracking, nearest node), `highlight` (the beam: `on`, `off`, `icon on|off`, `takeover on|off`, `size <0.5-2.5>`, `offset <pixels>`, `test`, `debug`), `unknown` (names the scan saw that aren't in the node lists - a missing node variant would show up here), `test` (compares the private and shared tooltips), `probe [step]` (one finer pass that lists every distinct minimap text with its hit count and hit-area size - for working out why a blip isn't picked up), `tracking on|off`, `tooltip shared|private`.

## Limits

- **Range is the minimap's.** The client only knows about objects near the player, so nodes beyond the minimap's view radius (233 yd fully zoomed out) cannot be seen by any addon. Zoom the minimap out for the widest range.
- **Only nodes the minimap shows.** That means the matching tracking spell must be on.
- **enUS names only.** The node list is matched by the tooltip's text; other locales need their names added to `Modules/NodeData.lua`.
- Position accuracy comes from averaging the probes that land on a node, a few yards in simulation; the arrow has pointed the right way in-game.

## Status

Written against build 70374 (interface 16001). The scanner, clustering, world-coordinate conversion and arrow were checked offline against a mock minimap that places nodes using independent compass geometry, with the minimap both fixed and rotating: recovered positions within a few yards and arrow direction within about a degree. Then run in the real game (build 70450): the arrow points at nodes on the minimap, including ones above or below you, the options window works, and tracking is switched on again after death.

The WoW: Forever beta closed after that, so the **light beam has not been run in the real game**; it is tested only against a mock client. To check it at release, use `/nf highlight debug` and look at: whether the client gives a readable name (or cursor icon) for a node as its soft target; whether the nameplate appears and the beam sits on the node (`/nf highlight offset` and `size` adjust it, and `/nf highlight test` marks any object so placement can be checked without a node); and how far away the game really picks a node up (debug reports it, measured against the minimap scan). If the beam hits repeated errors it stops itself and prints the reason instead of flooding the error window.
